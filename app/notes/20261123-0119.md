I attended the
[SREcon EMEA 2026](https://www.usenix.org/conference/srecon26emea)
conference in Dublin, Ireland in October where I presented a
[failover resilience project I've been working on for the last 6 years](https://www.usenix.org/conference/srecon26emea/presentation/mena)
with [Johan Mena](https://www.linkedin.com/in/johanmena).

Besides my own talk, I recommend these talks from others:

- [Performance Prompts](https://www.usenix.org/conference/srecon26emea/presentation/plenary-gregg)
  by Brendan Gregg.  This is a fairly practical talk including stories about
  having AI agents analyze and optimize software from low-level OS/GPU kernel
  optimizations to normal stateless services.  Brendan Gregg is well-known in
  the community for performance optimization tooling.
- [Perspectives from the Architecture of the Built Environment](https://www.usenix.org/conference/srecon26emea/presentation/plenary-oconnor)
  by Dave O'Connor.  Contrasting with Brendan Gregg's keynote, this is a more
  humanist talk about the benefits of choosing architecture that is more
  intuitive and easier for humans to work with.
- [Pull Requests Are Dead, Long Live Peer Review](https://www.usenix.org/conference/srecon26emea/presentation/ratcliffe)
  by Dylan Ratcliffe.  This talk addressed a problem I've been dealing with for
  a while which is how to make the best use of AI-generated coding and code
  review.  Rather than spending time on reviewing the output code, Dylan
  recommends reviewing the input plan sent to the AI.
- [Three Lies We Tell Ourselves about Disaster Recovery and What to Do about Them](https://www.usenix.org/conference/srecon26emea/presentation/alexander)
  by Colette Alexander.  This talk crystallized some of the strategy questions
  for my work on Uber's disaster recovery planning.
